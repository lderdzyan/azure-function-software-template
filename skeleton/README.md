## Configuration layout

Terraform configuration is stored as YAML rather than `.tfvars` files:

```text
config-generated/
└── ${{ values.environment }}/
    ├── globals.yaml
    └── functionapps/
        └── ${{ values.name }}.yaml
```

- `globals.yaml` contains environment-wide values and default tags.
- `functionapps/*.yaml` contains Function App-specific values.
- `infra/locals.tf` selects `${{ values.environment }}` through `config_environment` and loads the YAML with `yamldecode(file(...))`.
- `infra/validations.tf` checks that the selected environment and Function App configuration are complete.

## One-time setup

### 1. Create the Terraform state backend

Use a pre-existing Azure Storage account and private blob container for Terraform state. The state resources must exist before the first workflow run and must not be managed by this repository.

### 2. Configure Azure workload identity federation

Create an Entra application or user-assigned managed identity with a federated credential for this repository:

```text
repo:${{ values.destination.owner }}/${{ values.destination.repo }}:ref:refs/heads/main
```

Grant the identity:

- `Contributor` on the subscription or another scope that permits creation of `${{ values.resourceGroupName }}`;
- `Storage Blob Data Contributor` on the Terraform state storage account.

If Terraform plans are required on pull requests, add another federated credential whose subject matches the repository's pull-request subject claim.

```text
repo:${{ values.destination.owner }}/${{ values.destination.repo }}:pull_request
```

### 3. Configure the GitHub repository

Create these Actions secrets:

| Secret | Value |
|---|---|
| `AZURE_CLIENT_ID` | Client ID of the federated Entra identity |
| `AZURE_TENANT_ID` | Azure tenant ID |
| `AZURE_SUBSCRIPTION_ID` | Target Azure subscription ID |

Create these Actions variables:

| Variable | Value |
|---|---|
| `TF_STATE_RESOURCE_GROUP` | Resource group containing the state storage account |
| `TF_STATE_STORAGE_ACCOUNT` | State storage account name |
| `TF_STATE_CONTAINER` | Private blob container name |

No client secret is required.

The workflow is skipped until all three Terraform state variables exist. After completing the setup, run **Deploy Azure Function** manually once or push a change under `infra/`, `config-generated/`, or `function_app/`.

## Deployment behavior

- Pull requests run `terraform fmt`, `init`, `validate`, and `plan`.
- Pushes to `main` apply the plan and deploy `function_app/`.
- The Function App receives a stable random suffix stored in Terraform state.

After deployment, the workflow prints the endpoint. It has this form:

```text
https://<generated-function-app-name>.azurewebsites.net/api/hello?name=Babken
```

The response is JSON:

```json
{
  "message": "Hello, Babken!",
  "service": "${{ values.name }}",
  "status": "ok"
}
```
